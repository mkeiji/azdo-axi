## Why

`work-item show` passes `--project` to `az boards work-item show`, but the current Azure DevOps CLI rejects that unsupported option. Removing it is required for existing work-item reads to succeed while preserving the wrapper's resolved context and output behavior.

## What Changes

- Remove `--project <project>` from the Azure CLI argument list generated by the `work-item show` route.
- Preserve organization, JSON output, relationship expansion, context reporting, and error handling for show operations.
- Add regression coverage for the corrected argument list and successful response handling.
- Leave project arguments unchanged for create, update, list, and query routes.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `work-item-read`: The show route invokes the supported Azure CLI argument shape without a project option while retaining resolved project context in wrapper output.

## Impact

The affected implementation is the Azure argument construction and response handling for `work-item show`, with focused tests in the work-item test suite. No public wrapper options, dependencies, or other route behavior change.
